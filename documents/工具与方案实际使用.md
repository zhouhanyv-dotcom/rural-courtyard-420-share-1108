# 搜索、安装与实际使用记录 R3

不是只有两个。查阅了GitHub来源并安装5项技能；固定到当次提交，原文/来源哈希留在references/layout-tools。新安装技能可在后续对话自动发现，本次已经直接读其文档并用适用部分工作。没有把安装数量当作空间合理性的证据。

| 技能 | 本次实际用途 |
|---|---|
| facility-layout-optimizer | 从作业关系、面积、From-To动线及维护可达性分析院子；示例不是住宅合规或全局最优证明 |
| blender-core | 运行环境检查，保留既有Blender/GLB模型栈 |
| blender-scene-setup | 场景单位/集合/输出与scene_audit审计 |
| blender-hardsurface-modeling | 参考分件、接触和可制造外形，重建梯口、支撑、柜体、通路与水部件 |
| blender-asset-qa | 对新菜床框和搬运车执行数值QA、随机角度及线框联系图，实际结果另见验证记录 |

来源：[a5c-ai/babysitter的facility-layout-optimizer](https://github.com/a5c-ai/babysitter/tree/feb68abe397acc14f32b34984975c48fedba2b33/library/specializations/domains/science/industrial-engineering/skills/facility-layout-optimizer)，提交feb68abe397acc14f32b34984975c48fedba2b33；[EL4CTEO/blender-skills](https://github.com/EL4CTEO/blender-skills/tree/fb92cfb4cc5a238c22113a6a230b09f535bd0656)，提交fb92cfb4cc5a238c22113a6a230b09f535bd0656。两者MIT，许可副本随包。

Blender技能面向5.2+，本项目是4.5.3；没有为套技能强升版本。review_shots中5.2专有media_type枚举在项目兼容副本中加hasattr判断；安装原版保持不变，其余适用脚本实际运行后才计入结果。旧模型集合名/门窗部件及UV约定不做全库重命名。QA数值与随机联系图都不能替代实际总平面和关键近景审看。

| 方案/库 | 实际计算 | 边界 |
|---|---|---|
| Shapely 2.2.0 | 360m²地面多边形去重分区、菜床净面积/间距、带孔用途图三角化 | 不等于所有三维碰撞、消防或施工审查 |
| OR-Tools 9.15.6755 CP-SAT | 先固定走道与允许摆板区，求各区两种方向排板；结果46块200W | OPTIMAL仅对列明分区/方向候选成立，不是全院建筑全局最优 |
| NetworkX 3.6.1 | 人行与分段备板路线连通，主门阻断/侧门阻断分别检查 | 语义节点图不证明实体携带/门扇/高度全部无碰撞 |
| pvlib 0.16.1 | 太阳位置、菜床遮挡向量，代表日日照采样 | 不含真实天气和邻地，不是全年发电量/农业产量证明 |

另调查EmbodiedGen/spatial-computing，但其URDF/USD及room-cli/服务依赖不适合现有BLEND/GLB交付，未安装、未宣称使用；没有把不适用工具也一股脑下载运行。

Python依赖固定在scripts/layout-requirements.txt，计算源代码solve_r3.py、analyse_r3.py随scripts；模型权威数据为model/layout-plan.json、sun-and-flow.json、water-system.json、resources.json。最后模型几何、预算与网页必须一致，不能只看求解器返回成功。

官方方法：[Shapely](https://shapely.readthedocs.io/en/stable/manual.html)、[OR-Tools](https://developers.google.com/optimization/pack)、[NetworkX](https://networkx.org/documentation/stable/reference/algorithms/shortest_paths.html)、[pvlib](https://pvlib-python.readthedocs.io/en/stable/reference/solarposition.html)。

R3.3追加兼容修正：qa_check._mesh_world和review_shots._bounds使用依赖图求值后的世界矩阵/边界，避免Blender4.5隐藏集合切换后原矩阵缓存导致误报。安装原版不改；本次10组新资产的错误修正、接受的接触面/安装高度警告和逐对象三角形记录见当前验证记录及JSON。
